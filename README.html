Instagram Auto-Follow Agent

An intelligent Instagram automation tool that helps you grow your audience by automatically following targeted users from specific pools (posts or accounts).

Features

  • ✅ Browser Automation - Uses Puppeteer to mimic real human behavior
  • ✅ Smart Rate Limiting - Conservative 30 follows/day with intelligent delays (45-90s between follows)
  • ✅ Session Management - Persistent login with cookie storage
  • ✅ Pool Extraction - Extract users from post likers, commenters, or account followers
  • ✅ Database Tracking - SQLite database to prevent re-following and track stats
  • ✅ Advanced Human-like Behavior - Profile viewing, random skips, varied delays, non-sequential following
  • ✅ Action Block Detection - Automatically stops if Instagram blocks actions

Installation 

# Install dependencies
npm install

Usage

NEW: Two-Step Workflow (Recommended)

The agent now uses a separated workflow - extract users once, follow multiple times.

Step 1: Extract Users from Pool 

npm run extract <pool_url> <pool_type> [target_count]

Examples:

# Extract 200 followers (default)
npm run extract https://www.instagram.com/uclasubletting account_followers

# Extract 300 followers
npm run extract https://www.instagram.com/uclasubletting account_followers 300

# Extract post likers
npm run extract https://www.instagram.com/p/ABC123/ post_likers 200

What it does:

  • Scrolls modal to extract ALL usernames (aggressive extraction)
  • Saves users to database with status pending
  • Skips users already in database
  • Can extract 200-500+ users per pool (Instagram may limit scrolling)

Step 2: Follow Users from Queue 

npm run follow

What it does:

  • Pulls pending users from database (up to 15 per session)
  • Visits each profile and checks follow status
  • If "Already following" → Updates database (syncs phone/web follows)
  • If "Follow" button → Clicks and records to database
  • Follows up to 30 users per day across multiple sessions

Pool Types

  1. post_likers - Extract users who liked a specific post
  2. post_commenters - Extract users who commented on a post
  3. account_followers - Extract followers of an account

Old Single-Step Command (Still Works) 

npm start <pool_url> <pool_type>
# Extracts AND follows in one session

First Run

On first run, the browser will open and you'll need to:

  1. Login to Instagram manually
  2. The agent will save your session for future runs
  3. No need to login again on subsequent runs

How It Works (Current Workflow - Approach B Enhanced)

New Two-Step Workflow

Step 1: Extraction (npm run extract)

  1. Opens Instagram and navigates to pool URL
  2. Opens followers/likers modal
  3. Scrolls modal aggressively (up to 50 scrolls or target count)
  4. Extracts ALL usernames (simplified - no button detection)
  5. Saves to extracted_users table with status pending
  6. Skips users already in database
  7. Shows queue stats (pending, followed, total)

Step 2: Following (npm run follow)

  1. Pulls pending users from database queue (up to 15 per session)
  2. For each user:
    • Visits profile page
    • Checks "Following" button → Updates database (syncs manual follows)
    • Checks "Requested" button → Updates database
    • Finds "Follow" button → Clicks and records to database
  3. Database auto-syncs with Instagram reality
  4. Delays: 5-25 seconds between follows
  5. Session limit: 15 follows, Daily limit: 30 follows

Old Single-Step Workflow (v3.0 - Still Available)

Run npm start <pool_url> <pool_type> to extract and follow in one session.

Why Two-Step Workflow? (Approach B Enhanced)

Problem with old approach:

  • Instagram shows already-followed accounts FIRST in followers modal
  • Old extraction: Extract 30 → Likely all already followed → Wasted time
  • Manual phone follows NOT in database → Agent visits them anyway

Solution: Aggressive Extraction + Database Queue

1. Extract 200+ users aggressively (ignore who's followed)
2. Save ALL to database queue with status "pending"
3. Follow sessions: Pull from queue, check each profile
4. When "Already following" found → Update database (self-correcting)

Benefits:

  • ✅ Extract once, follow many times (reusable queue)
  • ✅ Database auto-syncs with Instagram over time
  • ✅ Build queue from multiple pools
  • ✅ No complex modal button detection (unreliable)
  • ✅ Profile-level checks are reliable
  • ✅ Resume-able workflow

Safety Features (Low Risk Configuration)

  • Conservative Daily Limit: Max 30 follows per day
  • Session Limit: Max 15 follows per session
  • Smart Extraction: Only extracts NEW users (skips already-followed during extraction)
  • Fast Delays: 5-25 seconds between follows (avg ~15s, still human-like)
  • Pre-Randomization: 75% selection applied BEFORE visiting (no wasted visits)
  • Minimal Post Viewing: 10% chance to view posts (balance speed/human behavior)
  • Non-Sequential: Users shuffled before processing
  • Random Pauses: Natural breaks every 3-7 follows
  • Action Block Detection: Auto-stops if Instagram blocks actions
  • Duplicate Prevention: Database + UI check (never re-follow/re-request)

Database Schema

extracted_users (NEW - Primary Queue)

  • username - Instagram username
  • extracted_at - Timestamp when extracted
  • pool_source - URL of the pool where user was found
  • pool_type - Type of pool (post_likers/post_commenters/account_followers)
  • follow_status - Status: pending, followed, already_following, already_requested, error
  • followed_at - Timestamp of follow action
  • notes - Additional info (error messages, etc.)

Follow Statuses:

  • pending - Not yet processed
  • followed - Successfully followed by agent
  • already_following - Detected "Following" button (manual follow from phone/web)
  • already_requested - Follow request pending (private account)
  • error - Failed to follow (button not found, etc.)

followed_accounts (Legacy - Still Used)

  • username - Instagram username
  • followed_at - Timestamp of follow action
  • pool_source - URL of the pool where user was found
  • status - Current status (followed/unfollowed)

pools

  • pool_url - URL of the pool
  • pool_type - Type of pool (post_likers/post_commenters/account_followers)
  • processed_at - Timestamp
  • total_extracted - Number of users extracted

daily_stats

  • date - Date
  • follows_count - Number of follows that day
  • pools_processed - Number of pools processed

Week 1: Build Queue

npm run extract https://instagram.com/competitor2 account_followers 200
npm run extract https://instagram.com/p/viral_post post_likers 200
# Queue now has ~600 users

Daily: Follow from Queue

# Morning session (15 follows)

# Evening session (15 follows)
npm run follow
# Daily total: 30 follows
# Queue lasts for 20 days (600 / 30)

As Needed: Refill Queue

# When queue drops below 100 pending
npm run extract <new_pool_url> account_followers 200

General Tips

  1. Build Large Queue First - Extract 200-500 users before starting follows
  2. Space Out Sessions - Run 2 follow sessions per day (morning & evening)
  3. Start Conservative - Begin with 20-25/day for the first week
  4. Choose Quality Pools - Select posts/accounts with your target audience
  5. Monitor Queue Stats - Commands show pending/followed/total counts
  6. Respect Limits - Don't try to bypass the 30/day limit
  7. Take Breaks - If action blocked, wait 6-12 hours before resuming
  8. Account Age Matters - Newer accounts should start with 15-20/day

Technical Deep Dive

This section documents the evolution of the agent and key technical challenges solved.

Version History:

  • v1.0: Basic extraction with XPath button verification

  • v3.0 (Current): Simplified click-and-record + reliable scrolling

Modal Scroll Fix (v3.0)

Problem: Modal wasn't scrolling at all, only extracting first 12 users visible.

Root Cause:

  • Original code: document.querySelector('div[role="dialog"] > div > div')
  • This selector didn't match Instagram's actual modal structure
  • Modal has scrollable element but not at that exact path

Solution - Multi-Strategy Scroll Detection:

// Strategy 1: Find ANY element with scrollHeight > clientHeight
const allElements = dialog.querySelectorAll('*');
scrollContainer = Array.from(allElements).find(el => {
  return el.scrollHeight > el.clientHeight;
});

// Strategy 2: Try direct children
if (!scrollContainer) {
  scrollContainer = document.querySelector('div[role="dialog"] > div > div');
}

// Strategy 3: Try the dialog itself
if (!scrollContainer) {
  scrollContainer = dialog;
}

Result:

  • ✅ Scroll now works reliably
  • ✅ Extracts 30+ users instead of 12
  • ✅ Method: "found-scrollable-element" (finds any scrollable element in modal)

Debug Output Example:

Modal structure: {
  found: true,
  childrenCount: 1,
  childrenTags: ['DIV'],
  hasScrollable: false  // Direct children not scrollable
}

Scroll result: {
  success: true,
  method: 'found-scrollable-element',  // Found deep in tree
  scrolled: true,
  scrollTop: 477,
  scrollHeight: 786
}

Key Insight: Instagram's scrollable element is nested deep in the modal, not a direct child. Strategy 1 searches ALL descendants to find it.

Button Detection Evolution

v1.0 - Complex XPath with Verification:

// Click button
clickByXPath("//button[contains(., 'Follow')]");
// Wait and verify state changed
const isFollowing = existsByXPath("//button[contains(., 'Following')]");

Problem: Button state verification failed, nothing saved to database.

v2.0 - Multi-Strategy Button Detection:

// Try to detect button state after click
const buttonState = page.evaluate(() => {
  const buttons = Array.from(document.querySelectorAll('button'));
  const followBtn = buttons.find(btn =>
    btn.textContent.includes('Following') || btn.textContent.includes('Requested')
  );
  return followBtn ? 'following/requested' : 'unknown';
});

Problem: Always returned "unknown" - couldn't reliably detect button state change.

v3.0 - Simplified Click-and-Record (Current):

// Click button
const followClicked = clickByXPath("//button[contains(., 'Follow')]");
if (followClicked) {
  // Immediately record as followed - no verification needed!
  addFollowedAccount(username, poolSource);
  incrementTodayFollowCount();
}

Result:

  • ✅ Works reliably
  • ✅ Database tracking now functional
  • ✅ Assumes click = success (Instagram rarely fails on click)

Key Insight: Button state verification is unreliable in Instagram's dynamic UI. Trust the click action instead.

Troubleshooting

"Action Blocked" Error

  • Instagram has temporarily blocked following
  • Wait 6-12 hours before trying again
  • If repeated: reduce daily limit to 20 or pause for 2-3 days

"Follow button not found"

  • Profile may be private or follow button UI changed
  • Agent will skip and continue to next user

Login Issues

  • Delete data/cookies.json and login again
  • Make sure you're not using 2FA (or handle it manually)

Logs

All actions are logged to:

  • Console: Real-time progress
  • Database: Persistent tracking (db/follow-agent.db)
  • Log Files: Daily logs in logs/ directory
